# 结构与兼容决策

## 文件去哪里

按现有责任划分，而不是按扩展名机械搬运。常见分区可参考维护源码／测试／工具／配置／当前指南／原始资料／验证证据／当前发布／历史归档／私人运行区。小项目不必为每类创建空目录。

根文件先识别消费方：入口说明、Agent规则、构建manifest、锁文件、启动器、用户数据。用户明确要求“根目录只留Agent入口、README和点文件”时，再把其他文件迁入固定目录；保留AGENTS.md等平台标准名。点文件不是通过改名绕开工具要求的手段。

| 情况 | 决策与完成证据 |
|---|---|
| Windows CMD移入子目录 | 重算`%~dp0`、cwd和解释器路径，从其他工作目录也能定位项目。能只读检查的入口，不用真实启停验证。 |
| PowerShell／Shell脚本 | 检查脚本自身目录、cwd、被调用脚本、配置和环境路径，而非仅替换文档。 |
| Python pyproject移入子项目 | 明确包发现与源码关系；更新pip安装、wheel、校验和导出清单；实际验证wheel、静态资源、editable和独立解压。原`pip install -e .`不能默认为仍有效。 |
| Node／Rust等根manifest | 工具可能要求位于workspace根。优先保留可用结构；用户坚持严格根目录时设计真正的子项目结构并构建验证，不是仅搬到config目录。 |
| 已安装应用与维护工程分离 | 保护安装路径与数据目录；当前运行和未来构建分别核验。源码结构变化不自动要求客户端升级。 |
| 历史收据里的绝对路径 | 保留当时证据，另建映射；读取旧路径的维护工具明确先恢复或作适配。 |

## 什么可以清理

| 类别 | 默认处理 |
|---|---|
| 字节码、编译中间文件、已完成打包临时目录 | 确认无人使用、可重建后删除，记路径／体积／理由。 |
| 重复展开的运行时 | 保留固定来源、版本与必要依赖；独有应用源码先归档。 |
| 原始源码、客户输入、正式完整源码交付 | 保留；同哈希或重复标签不能自动推导为无用。 |
| 日志、截图、结果和源码清单 | 解释验收／失败的证据保留，大量一次性过程文本可压缩；私人内容留私人区。 |
| 虚拟环境、node_modules、工具链、下载缓存 | 区分重建成本、固定版本、离线可用性及运行／构建引用，不按熟悉的目录名删除。 |
| 数据库、配置、审计、导出、密钥、配对 | 持久或私人资产，不靠日期、大小或名称判为缓存。 |

大量目录看似重复但缺少保留规则时，先选当前可用的一份为操作基线，旧版压缩或保留，避免未经验证的跨版本去重。

归档校验只证明快照内容可读，不证明在线数据库一致、服务兼容或新机器可安装。选择覆盖实际风险的检查，不扩大成产品改版、环境重装或实机操作。
